<objective>
Make `GenReflectionUI` report rather than silently skip: complete the whole
`mutable_config/` walk, aggregate every unresolvable config with its path, its type URL and
the Phase 13 diagnostic, return that aggregate, and log it only when the failure set
changes.

Purpose: today a resolver failure inside the walk closure does `return err`, which
terminates `filepath.WalkDir` — and `filepath.WalkDir`'s return value is not captured at
all, not even into `_`. One unresolvable config therefore silently loses every example
after it, at every call site, forever. That is precisely what CONS-04 forbids.
Output: an extracted `collectExamples` seam that returns `([]standalone.Example, error)`,
change-detection state on the server, explicit error handling at all four call sites, and a
test file that pins each of the four probe-surfaced CONS-04 edges.
</objective>

  <action>
Restructure `server/server.go` in four moves.

**(a) Extract the walk.** Add an unexported method
`func (s *ProtoconfMutationServer) collectExamples() ([]standalone.Example, error)` holding
everything currently between `examples := []standalone.Example{}` and the
`logger.Debug("examples", ...)` line. `GenReflectionUI` calls it, keeps the returned
examples for `standalone.WithExamples`, and folds the returned aggregate into its own
return value. The seam exists so a same-package test can assert on both the surviving
examples and the aggregate without reaching through `httpServer.Handler`; keep it
unexported.

**(b) Never abort the walk.** Inside the closure, every branch returns `nil`. The two
branches that currently `return err` after `FindMessageByURL` and after `UnmarshalTo`
instead append to a local failure slice and return `nil`. The `ReadConfig` branch, which
today logs and returns `nil`, appends to the same slice and returns `nil` — the two failure
paths must stop diverging. The closure's own leading `err != nil` parameter branch (a
directory I/O error surfaced by `WalkDir` itself) also appends and returns `nil`, so a
single unreadable subdirectory does not truncate the walk either.

Define a package-level unexported struct `reflectionFailure` with three fields: the
`mutable_config/`-relative path, the type URL (empty string when `ReadConfig` failed before
one was available), and the underlying error. Collect `[]reflectionFailure`.

**(c) Capture WalkDir's own return.** The enclosing `filepath.WalkDir(...)` statement must
assign its result — today it is not assigned even to `_`. A non-nil result there is a
directory-level error distinct from any per-file failure; fold it into the returned
aggregate alongside the per-file failures. Build the aggregate with `errors.Join` over one
`fmt.Errorf` per failure, each naming the relative path, the type URL, and the wrapped
underlying error, matching this repo's existing join idiom. Return `nil` when there are no
failures and no walk error. An absent `mutable_config/` directory must not be treated as a
failure of the server: `filepath.WalkDir` reports it through the closure's `err` parameter,
so decide once and encode it — a `fs.ErrNotExist` on the walk root yields zero examples and
a nil error, every other I/O error is collected.

**(d) Log on change, not per pass.** Add two fields to `ProtoconfMutationServer`: a
`sync.Mutex` and a string holding the previous pass's failure fingerprint. The fingerprint
is built from the failure slice by sorting a per-failure line composed of the relative path,
a separator, the type URL, another separator, and the underlying error's `Error()` text,
then joining the sorted lines. Sorting makes the comparison order-independent, so two passes
that surface the same failures in a different order compare equal; including the error text
makes a config that changes from one failure reason to a different one re-log, which
comparing paths alone would suppress. Under the mutex, compare the new fingerprint to the
stored one; log the aggregate with `logger.Error` only when they differ, then store the new
one. An empty fingerprint that follows a non-empty one is itself a change — log a recovery
line so an operator sees the failure clear.

**(e) Handle the returned error at all four call sites.** In `server/server.go` (the ticker
goroutine's call and the inline call after it) and in `devserver/command.go` (the inline
call and the ticker goroutine's call), assign the result explicitly rather than leaving a
bare statement. `GenReflectionUI` owns the log-on-change reporting, so the call sites must
not re-log — a second log line per site would reintroduce exactly the per-pass flooding
part (d) removes. Explicit assignment plus a one-line comment naming `GenReflectionUI` as
the reporter is the whole change. The ticker must keep running in every case: no `return`,
no `break`, no `os.Exit`, no server shutdown on a failed pass.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `mutable_config/*.materialized_JSON` on disk → the reflection-UI walk | Repository- and `MutateConfig`-authored JSON, including files a remote caller just wrote, crosses into descriptor resolution on a 5-second ticker |
| ticker goroutine ↔ inline caller | Two goroutines invoke `GenReflectionUI` on one shared server value |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-09 | Tampering | Change-detection state on `ProtoconfMutationServer` | high | mitigate | The ticker goroutine and the inline caller both reach the new fingerprint field, so it is guarded by a `sync.Mutex` held across the compare-and-store. `TestGenReflectionUIConcurrentCallsAreRaceFree` runs two concurrent passes on one shared server under `-race`, repeated with `-count=2`. |
| T-14-10 | Denial of Service | Aggregate and fingerprint retention | medium | mitigate | Only the CURRENT pass's fingerprint string is retained — no history, no per-path map that grows with every path ever seen. The aggregate is rebuilt per pass and discarded by the caller. A repository with many broken configs costs one string proportional to the current failure set, not to time. |
| T-14-11 | Denial of Service | Per-pass logging on a 5-second ticker | medium | mitigate | Logging only on a changed failure set is the control. Without it one persistently broken config emits roughly 720 lines an hour, which trains operators to filter the channel — the exact silent-failure-in-log-line's-clothing the phase forbids. Recorded as a prohibition in `must_haves`. |
| T-14-12 | Denial of Service | On-demand resolution inside the ticker walk | medium | accept | The walk is bounded by `mutable_config/`'s size, never by repository size, and each unresolved type costs at most 32 candidate parses plus one memoised index build per registry. A remote caller can enlarge `mutable_config/` only through `MutateConfig`, which is already behind `bearerTokenInterceptor`. Accepted as bounded and auth-gated. |
| T-14-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero dependencies added; `git diff --exit-code go.mod go.sum` must be clean at plan end. RESEARCH.md § Package Legitimacy Audit records "No new packages" for the phase. |
