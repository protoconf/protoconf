<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| N concurrent gRPC clients → one long-lived mutation server | Concurrent untrusted requests share one `*DescriptorRegistry` and one growable resolver |
| ticker reflection walk ↔ in-flight `MutateConfig` | A background goroutine reads the same registry the request handlers write |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-16 | Tampering | Shared `*utils.DescriptorRegistry` state under concurrent gRPC requests | high | mitigate | The `d.mu` lock discipline established in Phases 11-12 is the control; this plan's job is to PROVE it holds for the mutation server's newly-reachable lazy call paths. Task 1 exercises it end-to-end, Task 2 forces the interleaving continuously, and the lock-removal step proves the test can detect the failure rather than merely reporting green. |
| T-14-17 | Denial of Service | `ParseOne` deadlock under concurrent resolution | high | mitigate | Phase 11's discipline — never hold `d.mu` across `parser.ParseFiles`, because `protoparse` calls `LookupImport` from inside and that closure takes `RLock` — is what keeps concurrent tier work from self-deadlocking. Task 2's writers resolve distinct unparsed symbols concurrently, which is exactly the shape that would hang if the discipline were violated; a hang fails the test by timeout. |
| T-14-18 | Tampering | Temporary lock removal during the validation step | medium | mitigate | The removal is bounded to one task, targets one named matched Lock/Unlock pair, and is reverted with `git checkout -- utils/utils.go`. `git diff --exit-code utils/utils.go` is an acceptance criterion AND a verify command, so an unreverted removal fails the plan rather than shipping. |
| T-14-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero dependencies added; `errgroup` and `bufconn` are already direct/transitive dependencies. `git diff --exit-code go.mod go.sum` must be clean at plan end. |
</threat_model>
