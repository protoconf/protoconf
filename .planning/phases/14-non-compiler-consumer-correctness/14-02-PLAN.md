<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| subscribed gRPC client → `Store.Get` key | A caller-supplied key is joined onto `protoconfRoot` to form a filesystem path |
| `materialized_config/*.materialized_JSON` on disk → filekv parser | Repository-authored JSON carrying an arbitrary `@type` string crosses into descriptor resolution |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-03 | Information Disclosure | `Store.Get` key-to-path join, `agent/filekv/filekv.go` | high | transferred → 14-09 | The guard in place when 14-02 shipped rejected only a key that differed from its own cleaned form, which does not reject a leading `..` segment. `TestGetRejectsTraversalKey` as written by 14-02 could not detect that, because its fixture had no file at the traversal target. The risk was live until plan 14-09, which added a containment check (`resolveKeyPath`) and a test proven capable of failing against the unguarded code. |
| T-14-04 | Denial of Service | On-demand tier work moved into the request path by D-01 | medium | mitigate | A key whose type is unknown now triggers a scan (hard-capped at `scanCandidateLimit = 32` candidates, `utils/symbol_scan.go:42`) and at most one symbol-index build per registry (`ensureSymbolIndex` is singleflighted and content-key cached under `.protoconf_cache`). The cost is bounded per registry, not per request. Task 2's Test 2 pins the memoisation half. |
| T-14-05 | Spoofing | Resolved descriptor vs. requested type URL | medium | mitigate | `LoadSymbolByScan` treats a lexical match as a candidate only and re-checks `MessageRegistry.FindMessageTypeByUrl` after `ParseOne`. Test 1 asserts the served `Value.TypeUrl` equals the requested symbol exactly, so a near-match binding would fail the test. |
| T-14-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero dependencies added; `git diff --exit-code go.mod go.sum` must be clean at plan end. RESEARCH.md § Package Legitimacy Audit records "No new packages" for the phase. |
</threat_model>
