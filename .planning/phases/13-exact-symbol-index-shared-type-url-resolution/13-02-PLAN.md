<objective>
Build the exact symbol index: parse every `.proto` under `src/` without linking,
map every message and enum symbol — nested types included — to its declaring
file, persist that map under `.protoconf_cache` keyed by the tree's content
hash, and wire it in as Tier 3 behind 13-01's scan.

Purpose: TYPE-01/02/04/05/06/07. The scan handles the common case in
milliseconds; the index is the exact, complete answer the scan escalates to, and
it is what makes D-02's hard error defensible in 13-03 — a miss after the index
genuinely means the symbol is not under `src/`.

Output: `utils/symbol_index.go`, the persisted cache under `.protoconf_cache`,
three exported test-only counters, and Tier 3 wired into `resolveTiers`.
</objective>

<decided_discretion>
CONTEXT.md left six items to Claude's discretion. All six are decided here, with
the evidence the constraints required. An executor must implement these as
written, not re-open them.

1. **Symbol-kind coverage: messages AND enums.** Rationale: the index is a *path*
   lookup, so kind coverage only decides which symbols can be *looked up*. The
   resolver's surface is messages (`FindMessageByURL`/`ByName`); extensions stay
   snapshot-only (`parser.go:106-115`, RESEARCH.md A3). Enums cost one extra
   field read per level in a walk that already recurses, and D-02 turns any miss
   into a hard failure — breadth is cheap insurance against a one-way decision.
   Services and extensions are excluded: nothing resolves them by symbol.
2. **Cache key: `dirhash.HashDir(root, "", dirhash.Hash1)` per import root.**
   Measured this planning session over the 799-proto / 37.8 MB corpus:
   **~30ms warm** (34.3 / 30.1 / 28.6 ms), against a 1,286ms build. One
   mechanism, already a direct dependency, already the module-repo cache key
   (`compiler/lib/module_service.go:273`). It hashes every file under the root,
   not only `.proto` — a strict superset of TYPE-06, so it can only ever cause
   MORE work, never a stale serve, which is exactly the one-way direction the
   constraint demanded.
3. **Escalation rule: the scan escalates when it finds zero candidates, when no
   candidate verifies, or when the match count exceeds `scanCandidateLimit`
   (32, derived and recorded in 13-01).** If the rule never fires in practice,
   `IndexBuildCount()` staying 0 across a real workload is the visible evidence
   CONTEXT.md asked for — record it in this plan's SUMMARY.
4. **On-disk format: a line-oriented text file with a versioned header.** Line 1
   is `protoconf-symbol-index/v1 <contentKey> <entryCount>`; each later line is
   `<symbol>\t<root-relative path>`, sorted by symbol. Rationale: the artifact
   only has to answer "path for symbol X", the *validation* is the content key
   rather than a serialization checksum, and this needs no `protoc`
   regeneration step. This deviates from RESEARCH.md Open Question 2's proto
   suggestion for that last reason; the header's entry count plus an atomic
   temp-file-and-rename write covers the truncation failure mode a proto's
   length-delimited framing would have covered.
5. **Singleflight: yes, reusing the existing `d.group` field** with the fixed key
   `"\x00symbol-index"` — a NUL-prefixed key cannot collide with a path, since
   `ParseOne` rejects anything failing `filepath.IsLocal`. No second
   `singleflight.Group`.
6. **Concurrency contract: Phase 11's lock discipline, unchanged.** Read config
   under `RLock`, release, do all filesystem and parse work unlocked, take
   `Lock` only for the map install and counter bump.
</decided_discretion>
