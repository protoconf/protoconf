<objective>
Execute D-02: delete the whole-tree eager fallback as the resolution chain's last
tier, replace it with an engineered hard error, and replace — not delete — the
operator-observability contract the old fallback carried.

Purpose: the 4.6s `GetProtoRegistry()` path this milestone exists to remove is
only *unreachable* once nothing in the tree can call it. This plan makes that a
compile-time fact rather than a convention, and turns a resolution failure into a
fast diagnostic instead of a slow success.

Output: a NotFound-wrapping hard error naming the URL, the roots searched and the
index state; the whole-tree fallback method, its latch and its accessor removed;
four existing tests re-pointed at the new mechanism rather than deleted.
</objective>

This is one atomic change: removing the method breaks compilation until every
caller and test is repaired, so do not commit a partial state.

In `utils/utils.go`: remove the whole-tree eager fallback method, the boolean
latch field it sets, the exported accessor that reports it, and the mentions of
the latch in `mu`'s guards-what comment. Leave `Import`, `Parse`,
`registerFileLocked` and `recordFileLocked` untouched — `Import`/`Parse` are
still `mod sync`'s whole-tree path and have callers outside resolution.

In `compiler/lib/parser/parser.go`: remove the fallback call and its retry from
`resolveTiers`, so an exhausted chain falls straight through to the error. Build
that error as D-02 specifies — wrap `protoregistry.NotFound` with `%w`, exactly
as the existing convention does, and add the unresolved type URL, the roots that
were searched (`r.registry.ImportPaths`), and `r.registry.IndexState()`. Wrapping
rather than replacing the sentinel is what keeps every existing
`errors.Is(err, protoregistry.NotFound)` caller working; there are callers in
`server/`, `inserter/` and `mutate/` that this phase does not touch (D-03).

In `compiler/lib/compiler.go`: the compile-finished line currently reports
`protoFilesLoaded` and a boolean naming the old fallback. Keep `protoFilesLoaded`
and replace that boolean with three attributes read from the registry:
`symbolIndexBuilds` from `IndexBuildCount()`, `symbolIndexCacheHits` from
`IndexCacheHitCount()`, and `scanResolutions` from `ScanResolutionCount()`.
Report all three on every compile, including when they are zero — a line that
only appears when something escalated would leave "absent" and "did not
escalate" indistinguishable, which is the exact property the test being replaced
was written to pin.

`git mv compiler/lib/eager_fallback_visible_test.go compiler/lib/tier_observability_test.go`
and rewrite its two subtests against the new attributes, keeping
`recordingHandler`, `attrOf` and the "assert on the structured attribute rather
than formatted text" rationale intact. Subtest one: a corpus compile that
escalates nothing must still carry all three attributes, each zero. Subtest two:
after a compile that did escalate to the index, the reported value agrees with
the registry's own counter. This preserves the test's intent — an expensive tier
must never fire invisibly — under the new tier names, which RESEARCH.md Pitfall 1
requires rather than deleting it.

`git mv utils/parse_all_deadlock_test.go utils/index_build_deadlock_test.go` and
re-point it: keep `deadlockCorpus`, the `errgroup`, the 30-second `select` guard,

guard, and the `require.Same` pointer-identity loop. Replace the goroutine that
drove the whole-tree fallback with one that drives the index build via

driven directly (still a bulk path, still reachable from `mod sync`) so the
registration-diff contract stays pinned, or — if that proves to assert nothing

record that reasoning explicitly in the SUMMARY. Do not delete them silently.

In `utils/lazy_parse_canonical_test.go`, `TestParseOneReturnsCanonicalPointerWhenRacingParseAll`
