<objective>
Make the mutation server's gRPC service catalog independent of what the compiler's registry
happens to contain: `Init()` discovers custom services declared under `src/` with its own
one-time eager filesystem scan instead of ranging the parser's construction-time resolver
snapshot.

Purpose: `Init()` runs exactly once, at server startup, strictly before any config has been
compiled. Once the registry it reads from becomes lazy, that snapshot is near-empty and a
service defined in `src/myservice/api.proto` is never registered — for the entire process
lifetime, with no error, no log and no retry. The server starts fine and the service is simply
unreachable.
Output: `Init()` on a dedicated discovery registry, plus the test that proves it.
</objective>

<locked_decisions>
- **D-02:** the new eager discovery scan is scoped to gRPC **service registration only**. It does
  not also back gRPC server reflection — `Init`'s `reflection.NewServerV1` /
  `reflection.NewServer` calls keep using `s.parser.FilesResolver` and `s.parser.LocalResolver`
  unchanged. Reflection completeness under a lazy registry is a Phase 14 question, and
  criterion 5 of this phase says nothing about it.

  stays eager for non-compiler consumers this phase. This plan therefore does not depend on plan
  `11-01` and runs in the same wave: the discovery fix is structural, not a reaction to a
  behavior change that has already landed.
</locked_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `src/**.proto` → `Init`'s discovery scan → `rpcServer.RegisterService` | A proto file in the repository now determines, at startup, which gRPC services the mutation server exposes. This link already exists today; this plan changes which registry supplies it. |
| gRPC client → dynamically registered mutation method | Unchanged by this plan: the handler closure, `Put` and `MutateConfig` are copied verbatim. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-06 | Denial of Service | `Init`'s discovery scan on a repository containing a malformed `.proto` | medium | mitigate | `Import`'s error is logged via `logger.Error` and startup continues, matching `GetProtoRegistry`'s existing handling. A parse failure in one file must not prevent the server from starting and serving the services it could discover. |
| T-11-07 | Tampering | duplicate service registration via a `src/` proto declaring a service name that collides with a built-in | medium | mitigate | The existing `protoregistry.GlobalFiles.FindFileByPath(fd.Path())` skip in the discovery callback is preserved verbatim. `grpc.Server.RegisterService` panics on a duplicate name, so removing that guard turns a crafted proto into a startup crash. `TestInitRegistersCustomService` asserts exactly one entry for the discovered service and that `Init` does not panic. |
| T-11-08 | Elevation of Privilege | a service discovered from `src/` gaining a mutation handler | low | accept | The scan discovers strictly the same class of service the snapshot-based loop discovered — the `ConfigMutationResponse` output-type filter and `HandlerType` are unchanged. `src/` is repository-controlled content in every current deployment shape, the same trust level as the code being run. |
| T-11-09 | Information Disclosure | the discovery scan reading files under `src/` that no config loads | low | accept | Identical to today's `GetProtoRegistry` eager import, which already reads every `.proto` under `src/` at server construction. No new file is read that was not read before. |

No package-manager installs occur in this plan, so the package-legitimacy gate does not apply and
no `T-11-SC` row is required.
</threat_model>
