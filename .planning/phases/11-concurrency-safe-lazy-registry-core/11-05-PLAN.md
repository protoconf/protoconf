<objective>
Close `G-11-7`: `protoconf mod sync` silently writes zero-byte `.fds` files and overwrites
`protoconf.lock`'s real `fileDescriptorSetSum` values with the md5 of the empty string, while
exiting 0. Put one guard at the only point that converts an empty parse into persisted corruption,
stop the walk from erasing a failed dependency's error, and pin both at the `mod sync` CLI level —
the level at which the existing registry-level test was structurally unable to see this.

**`G-11-7` is PRE-EXISTING, not a Phase 11 regression.** It reproduces byte-identically on
`b69e3b2`, the commit before Phase 11 began (verified during UAT in a throwaway git worktree with a
separately built binary). It is being closed under Phase 11 by explicit user decision, exactly as
`G-11-3` was, so the requirements ledger must not attribute it to LAZY-01..05 or CONS-01. This
plan's `requirements: [LAZY-04]` reflects that `mod sync`'s `.fds` output is LAZY-04's subject
matter; `G-11-7` itself is tracked by `gap_ids`.

Purpose: `Import` over a path that does not exist returns no error, because `find()` ignores
`filepath.WalkDir`'s return value. `GenFileDescriptorSet` therefore parses zero files, `Store`
serializes an empty `FileDescriptorSet` into a zero-byte file, returns the md5 of empty, and the
closing `Walk` persists that md5 over the dependency's recorded sum. Every guard on that path
(`Load`'s cache miss, `Import`'s parse-failure check, `Store`'s write error) is on the wrong side
of the failure. The next `GetProtoRegistry` then loads the zero-byte set, its checksum matches the
now-corrupt lock, and every consumer believes it verified something.

Output: one read-only accessor in `utils`, one guard plus one accumulator fix in
`compiler/lib/module_service.go`, three existing test fixtures corrected to carry the `source_path`
a real lock file always has, and a `mod`-level regression test with three subtests — the two
corruption triggers and a good-path control whose expected checksums come from the committed
fixture.
</objective>

## The corruption, reproduced (unmodified binary)

Fixture: `cp -R utils/testdata/small $TMP/fixture`, then empty `$TMP/fixture/.protoconf_cache/`
(keep the directory). The committed lock has no `getterUrl` on either dep.

`protoconf mod sync -protoconfPath $TMP/fixture` prints `Parsing protos.` / `Storing in cache.`,
**exits 0**, writes `terraform_repo.fds` and `vizceral_repo.fds` at **0 bytes**, and rewrites both
`fileDescriptorSetSum` values from `6556e5cfb73f535f9b91738dbd0df926` /
`039f1e1023250b34054894cc58bc8b2b` to `d41d8cd98f00b204e9800998ecf8427e`.

## A SECOND trigger, also reproduced — this one shapes the fix

Run `mod init` first (so `getterUrl` is populated and both archives extract into
`.protoconf_cache/<label>/`), then set `terraform_repo.sourcePath` to a directory that does not
exist inside the extracted archive, delete the `.fds`, and sync again. **Identical corruption**:
exit 0, zero-byte `.fds`, both sums rewritten to the empty md5 — with the repository fully
downloaded and `getterUrl` correctly set.

This is why the guard must be keyed on the resolved proto paths yielding nothing, **not** on
`GetterUrl == ""`. A `Download`-level fix would leave this shape broken. `Download` returning early
on an empty getter url is also load-bearing for the head repository (`url: "."`), which never has
one; `Sync`'s second walk already exempts the head from `GenFileDescriptorSet` via its
`r.Url == "."` skip, which is precisely what makes a guard *inside* `GenFileDescriptorSet` safe.

## Why the emptiness signal is `localFiles`, not the descriptor set

`Store` iterates `d.localFiles`, which `Parse` resets to empty at its top and repopulates per
dependency. `GetFileDescriptorSet()` ranges `FileRegistry` instead, which `NewDescriptorRegistry`
seeds with ~65 well-known types before any parsing happens — it is never zero and cannot detect
this. `localFiles` is unexported, so `compiler/lib` needs a one-line read-only accessor. There is
no existing one: `LoadedFileCount()` returns `len(d.lazyLoaded)`, a different set.

## The fix shape, measured across four scenarios

Three edits: a `LocalFileCount()` accessor in `utils/utils.go`, a `LocalFileCount() == 0` guard in
`GenFileDescriptorSet` placed between the `Import` error check and `Store`, and `walk()`'s
`err = errors.Join(walk(deps[i], walkFn))` corrected to accumulate into `err`.

| scenario | today | after this plan |
|---|---|---|
| both deps unsynced (no `getterUrl`), cache emptied | exit 0, two 0-byte `.fds`, both sums -> empty md5 | **exit 1**, no `.fds` written at all, both sums intact |
| one dep downloaded with a bad `sourcePath`, one good | exit 0, 0-byte `.fds` for both, both sums -> empty md5 | **exit 1**, only the good dep's `.fds` written (2.7K), both sums intact |
| good path (`mod init` then `mod sync`) | exit 0, 15M + 2.7K `.fds`, real sums | **unchanged**: exit 0, 15M + 2.7K, sums restored to `6556e5cf...` / `039f1e10...` |
| no `.protoconf_cache/` directory at all, `getterUrl` set | exit 0, `getter.GetAny` creates it | **unchanged**: exit 0 |

The one-word `walk()` change is load-bearing and was measured separately: **with the guard but
without it, the one-bad-one-good scenario still exits 0**, because `walk` assigns rather than
accumulates and the later-processed good dependency's nil overwrote the failure. The lock stayed
intact (the non-negotiable held), but the operator got a success exit code after a real failure —
the "silent success" class this phase's UAT exists to catch.

## Three existing subtests go red, and they are asserting the bug

`TestModuleService_Sync`'s `no integrity`, `good integrity` and `download deps` cases build
`*module.RemoteRepo` structs by hand and **never set `SourcePath`**. `protoPaths` skips empty path
components, so those cases resolve to an EMPTY path list, parse zero files, and store a zero-byte
descriptor set — today they pass while asserting nothing about the generated output. The Starlark
`remote_repo` builtin defaults `SourcePath` to `"src"` (`ModuleService.Add`), so no real lock file
ever has this shape.

Adding `SourcePath: "src"` to those three fixtures makes all of `TestModuleService_Sync` pass under
the guard, **including the network-dependent `download deps` case** — `github.com/protoconf/protoconf-xds`
does have a `src/`. Measured. This is a strengthening: the subtests now exercise real descriptor
generation instead of silently generating nothing.

## Fixture facts the tests depend on

`testdata.SmallTestDir()` copies the embedded `small` fixture into a fresh `os.MkdirTemp` directory
(NOT the repository, and NOT `t.TempDir()` — it is not auto-removed), `git init`s it, and
**decompresses `internal/*.fds.gz` into `.protoconf_cache/*.fds`** — so the copy starts with valid,
non-empty descriptor sets whose checksums match the committed lock. A test that wants the parse
path must delete those `.fds` first, exactly as the UAT reproduction did, or
`GenFileDescriptorSet`'s `registry.Load` short-circuits with "Loaded from cache."

The repository's own `utils/testdata/small/.protoconf_cache/` currently holds two 0-byte `.fds`.
They are gitignored (`.gitignore:9`), untracked local build artifacts — no committed file is
corrupt, and `utils/testdata/small/protoconf.lock` on disk still carries both real sums.

## Out of scope, with the evidence for why

- **`mod sync` and a missing `.protoconf_cache/`.** Measured: with `getterUrl` set,
  `getter.GetAny` creates the directory and sync succeeds; `mod init` also creates it via
  `os.MkdirAll`. The only shape where the missing directory produced a failure was the
  no-`getterUrl` shape, which is `G-11-7` itself and now fails earlier with an actionable message.
  No reachable case remains, so no `MkdirAll` is added.
- **`walk()`'s `keys`/`deps` index mismatch.** `keys` is sorted but `deps` is built in map-range
  order, so `deps[i]` does not correspond to `keys[i]` and the sort is a no-op. Pre-existing
  ordering nondeterminism only; with the accumulator fix the exit code no longer depends on walk
  order, so nothing in this gap needs it. Do not fix it here.
- **`Import`/`find`/`Parse`'s tolerance of a missing path.** The true root cause of the silence,
  and deliberately left alone — see this plan's first prohibition.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.protoconf_cache/<label>/<sourcePath>` on disk -> `Import` / `find` | An absent directory is indistinguishable from an empty one, because `find` discards `filepath.WalkDir`'s error. The parse result crosses from "nothing was there" into a persisted artifact and a lock-file checksum with no error in between. |
| `registry.Store` output -> `.protoconf_cache/<label>.fds` -> every later `GetProtoRegistry` | The cache file and the lock's `fileDescriptorSetSum` are written together and verified against each other. A self-consistent empty pair passes `Load`'s checksum test forever, so every downstream consumer believes it verified something. |
| `protoconf.lock` on disk -> `modSyncCommand.Run`'s `defer c.ms.Lock()` | The lock is rewritten on every run including failing ones, so the operator's recorded checksums are only as safe as the in-memory `m.head` at the moment the deferred write fires. |
| `mod sync` exit code -> CI/CD pipelines | Pipelines gate on exit 0. A success code after a failed generation ships an empty descriptor cache downstream. |
| `protoconf.lock` `label` / `sourcePath` values -> `filepath.Join(getCacheDir(), label, path)` | Lock-file-controlled strings become filesystem paths. Pre-existing, unchanged by this plan. |
