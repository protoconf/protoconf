<objective>
Add a `-starlark-profile <file>` flag to `protoconf compile`. When set, the flag calls go.starlark.net's `starlark.StartProfile(w)` before the compile and `starlark.StopProfile()` after it. The result is a gzipped pprof profile that shows wall time per Starlark function and line. Today a CPU-bound compile can only be inspected with `-cpuprofile`, and the Go CPU profile attributes all Starlark work to `starlark.Call`.

Purpose: per-Starlark-function attribution for slow compiles, readable with `go tool pprof -top <file>`.
Output: one new proto field, the regenerated .pb.go, about 15 lines in `cliCommand.Run`, and one test.

Flag-name check (done during planning): libprotoconf v0.1.0 `PopulateFlagSet` (flagset.go:166-176) names each flag after `FieldDescriptor.JSONName()`, and it names env vars `toEnvKey(prefix, field.Name())`. `cpuprofile` is a single word, so its JSONName is just `cpuprofile`. A multi-word field with no annotation would get the camelCase JSONName `starlarkProfile`. Every multi-word field in this proto sets a kebab-case json_name instead (`process-templates`, `compiler-address`). Following that convention, the field is `string starlark_profile = 8 [json_name = "starlark-profile"]`, which gives the flag `-starlark-profile` and the env var `PROTOCONF_COMPILER_STARLARK_PROFILE`.

Field-number choice: use 8, not 7. This branch (`feat/starlark-profile`) was forked from origin/main, which ends at `compiler_address = 6`. Local `main` also has unpushed commits 1c76af72/17aa3ce4/290582df (quick task 260925-k4y), and those already use `log_level = 7`. If this branch used 7, the two branches would assign the same wire number to different fields, and git would not flag it as a conflict. Using 8 is safe however the two branches get merged. Leaving 7 unused on this branch is harmless in proto3. Do NOT add `reserved 7`, because that would break the log_level change when it lands.
</objective>

Reference only (do NOT modify): the go.starlark.net profiler API, at $(go list -m -f '{{.Dir}}' go.starlark.net)/starlark/profile.go:
- `func StartProfile(w io.Writer) error` returns an error if a profile is already running. The profiler is process-global, and Start must not be called while Starlark is executing.
- `func StopProfile() error` closes `profiler.events`. If no profile was started, that channel is nil, so the call panics with "close of nil channel". Only call it after StartProfile has succeeded.
- All output goes through bufio(4KB) and then gzip, and it is written only when StopProfile runs (`gz.Close()` + `bufw.Flush()`). The test relies on this: a non-empty file that is a valid gzip stream proves that StopProfile ran.

`go.starlark.net/starlark` is already imported in compiler/command.go (the REPL uses it), so no new import is needed there.
