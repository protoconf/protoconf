<objective>
Make `protoconf insert` fast when one call inserts many configs. Today `GatherMetadata` walks the git history once per file. Replace that with one walk per insert call that builds a path-to-last-commit map for all requested paths and stops when every path is found. The metadata must stay byte-for-byte identical.

Purpose: on the user's repo (3,050 commits, 122 configs) one insert call takes 711-737 s, about 6 s per file. The goroutine dump shows the time in Run.func1 -> InsertConfigFile -> GatherMetadata -> go-git commitPathIter.Next -> getNextFileCommit -> DiffTree -> merkletrie.DiffTreeContext. The cost is O(files x commits) because each file walks history on its own, serialized by the global metaMutex.

Output: a benchmark and equivalence harness measured before the change, the single walk wired into Run, before/after benchmark and profile files, parallel-vs-sequential numbers, and a PR.
</objective>

<design_notes>
The planner checked these in the code (go-git v5.19.3, the version in go.sum). The executor should not re-derive them.

- What GatherMetadata takes from git: the first commit of `i.repo.Log(&git.LogOptions{FileName: &configFile})`. It reads Hash, Committer.Email, Author.Email, and Committer.When for both CommittedAt and AuthoredAt (keep that quirk). It stamps InsertedAt with timestamppb.Now() at call time. Non-git: `{Commit: "not_a_git_repo"}`. A Log error is wrapped as "error getting git log for file %s". A Next error (io.EOF when the file was never committed, ErrObjectNotFound in shallow clones) is wrapped as "error getting next git log item for file %s". Both use errors.Join. The global metaMutex serializes every call.
- What Log with FileName does (repository.go Log/log, commit_walker_path.go): it resolves HEAD, builds `object.NewCommitPreorderIter(head, nil, nil)`, and wraps it in a path iterator with checkParent=false. getNextFileCommit diffs each commit's tree against the tree of the NEXT commit in iteration order, not its real parent (this matters for merges), and against a nil tree after the last commit. A commit matches when a Change's name equals the path. The name is From.Name if From is not the zero ChangeEntry, else To.Name (change.go name(), unexported). DiffTree does no rename detection. A non-EOF error from the source iterator, Tree(), or DiffTree aborts the walk with that raw error.
- Why one walk is equivalent: `i.repo.Log(&git.LogOptions{})` returns the exact same preorder source iterator without the path wrapper. Walk it once, diff each adjacent pair once, and for each change name that is still pending, record the current commit (first hit wins). Every per-file walk would visit the same pairs in the same order. So a path found at pair k gets the same commit. A path still pending when the walk hits an error at pair j gets that same raw error. Paths still pending after the last pair (diffed against nil) get io.EOF.
- Step order inside the loop must mirror getNextFileCommit, so the first error hit is the same one: (1) Next on the source iterator for the parent, where io.EOF means a nil parent and any other error aborts; (2) on the first pass only, Tree() of the current commit; (3) Tree() of the parent if it is not nil; (4) object.DiffTree(currentTree, parentTree); (5) match names; (6) if the parent is nil, the remaining paths get io.EOF; (7) the parent and its tree become current. Before the loop, an error from the first Next is recorded for every pending path (commitPathIter.Next returns it raw).
- If `i.repo.Log(&git.LogOptions{})` itself fails (unborn HEAD in an empty repo, bad HEAD), the prefetch records nothing. The per-file fallback then reproduces the "error getting git log" wrapper exactly. Do not invent a new error path.
- Cache lifetime: test/e2e_test.go inserts the same file again after new commits on the same inserter. So the map lives only for one insertConfigFiles call. It is set before the goroutines start and cleared (under metaMutex) after wg.Wait. GatherMetadata keeps its isGit check first, then the map lookup, then the unchanged per-file Log walk on a miss. The metadata is built in one shared tail for both paths, with InsertedAt computed there.
- Shallow clone in tests: the orchestrator suggested go-git CloneOptions{Depth: N} from a local path. go-git's file transport runs the external git-upload-pack binary (plumbing/transport/file/client.go), so that needs the git CLI. Simulate the clone instead. Build a linear repo, call repo.Storer.SetShallow with the cut commit, and delete the cut commit's parent with `repo.Storer.(storer.LooseObjectStorer).DeleteLooseObject(hash)`. Then open fresh repo instances. The preorder walker then fails with plumbing.ErrObjectNotFound when it loads that parent, which is what a real shallow clone does in go-git.
- The git CLI is not used anywhere, including tests. go-git can do the single walk on its own.
- Known unrelated bug, do not fix: ensureConfigMaterialized appends consts.CompiledConfigPath instead of CompiledConfigExtension.
</design_notes>
