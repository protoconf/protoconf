<objective>
Add a `-log-level` flag to `protoconf compile` so that the `slog.Debug` calls already in the compile path (for example compiler/template.go, compiler/lib/module_service.go:336, utils/symbol_scan.go) can be seen. Right now they never show, because Go's default slog logger drops everything below Info.

Purpose: let people debug compile problems without code changes.
Output: one new proto field, the regenerated .pb.go, 5 to 8 lines in `cliCommand.Run`, and one test.

Design choice (Claude's discretion; the orchestrator asked to mirror the agent's enum): the new field is a plain `string`, not a copy of the agent's `LogLevel` enum. The reason is a bug in libprotoconf v0.1.0: `flaggable.String()` (flagset.go:36) looks up enum values by their number as if it were a list index. `PopulateFlagSet` calls `String()` after `Environment()` has already applied env vars, so any non-INFO enum value set through the env var panics at startup. This was reproduced here: `PROTOCONF_AGENT_LOG_LEVEL=DEBUG protoconf agent -h` fails with `index out of range [-4]`. The string field avoids that bug. Parsing it with the standard library's `slog.Level.UnmarshalText` gives the same names as the agent (DEBUG/INFO/WARN/ERROR), and case-insensitive input comes for free.
</objective>
