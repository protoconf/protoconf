## Decisions Made
- **Option-b over option-a:** The plan's Task 1 checkpoint was pre-resolved by the user as `option-b` before this executor started. Rationale (recorded in the plan and carried forward here): v1.4.0 is not a mechanical bump — it renames the module to `buf.build/go/protovalidate`, raises the Go floor to 1.26.0, and permanently deletes the `legacy/` package (and the `StandardConstraintResolver` extension point it used) that lets protoconf enforce protoc-gen-validate `(validate.rules)` annotations. `compiler/lib/compiler_test.go:54` is a standing test proving PGV enforcement, and CLAUDE.md lists backward compatibility with existing config repos as a hard constraint. v0.8.0 is the newest release that still ships `legacy/`, satisfying that constraint with the smallest possible diff (go.mod/go.sum only).
- **Do not retry v1.4.0 casually:** A future upgrade to v1.x will require a deliberate, separately-announced breaking change to protoconf (dropping PGV support, raising the Go floor, deleting the `legacy_buf_validate.pconf` fixture and its test case) — this is option-a from the plan, not something to attempt as a routine dependency bump.
