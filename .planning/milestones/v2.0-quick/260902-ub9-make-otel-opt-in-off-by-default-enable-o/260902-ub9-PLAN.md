<objective>
Make OpenTelemetry opt-in for the agent and the mutation server. Off unless an operator explicitly asks for it.

Purpose: today both binaries unconditionally build OTLP/gRPC trace and metric exporters and install a per-RPC otelgrpc stats handler. With no collector on the network -- the common case -- that buys background exporter goroutines, a permanently-retrying gRPC connection, and per-RPC instrumentation work, in exchange for nothing. Opt-in is the correct default for a daemon that ships as a library-ish component.

Output: one `enable_otel` bool per config proto, one `enabled` parameter on `observability.Init`, four conditional call sites, and tests proving the default is silent.
</objective>

**Pre-decided design calls -- implement these, do not relitigate:**

- **D-01 -- Change the `Init` signature rather than adding a sibling function.** `Init(ctx context.Context, serviceName string, enabled bool)`. There are exactly two callers, so the compiler forces both to be updated and the decision becomes impossible to forget. A separate `InitIfEnabled` would leave the ungated `Init` on the package surface for a future caller to reach for by accident.
- **D-02 -- The gate lives inside `Init`, not in the callers.** Both callers do the identical thing today. One guard in the shared function is a smaller diff than a guard in each caller, and it covers callers that do not exist yet.
- **D-03 -- When disabled, install noop providers *explicitly*.** Do not rely on the OTel global default already being noop. Explicit installation holds even if something else in the process set a real provider first, which is the only behavior an operator can reason about.
- **D-04 -- Omit the `grpc.ServerOption` when disabled.** Do not write, port, or vendor a no-op stats handler type. Omitting an option from a slice is less code than substituting a handler, and it removes the per-RPC allocation rather than shrinking it.
- **D-05 -- Exactly one control mechanism.** The proto-derived flag/env pair is it. Do not add a second switch keyed on any OpenTelemetry SDK environment variable. Two controls create precedence questions nobody asked for. (Recommendation for a future task, explicitly NOT built here: if operators later want the standard SDK env var honored, that belongs in a separate change that defines precedence deliberately.)
- **D-06 -- Leave `otelkv.New` alone.** `agent/agent.go:119` and `:121` wrap the KV store with tracing spans off the global tracer. Under noop providers that is a nearly-free no-op span, and gating it would mean threading a bool into the store wrapper for no measurable gain. Record the decision in the SUMMARY; change no code there.
- **D-07 -- Leave `slogotel.OtelHandler` alone** (`agent/agent.go`). It reads span context from the global tracer; under a noop provider there is no span and it is a pass-through.
- **D-08 -- Leave `grpc_prometheus` alone.** It is Prometheus, not OpenTelemetry, and it is out of scope.
