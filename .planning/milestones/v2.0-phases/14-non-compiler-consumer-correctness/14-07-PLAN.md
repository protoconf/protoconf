Prove SAFE-02 for the agent with the same two test kinds D-07 requires of the mutation
server, and prove them against the real agent path rather than a stand-in: a
`ProtoconfKVAgent` backed by the now-lazy `filekv` store, whose `Watch` loop calls `Get`,

with `filekv` is what makes concurrent `SubscribeForConfig` a genuine concurrent-resolution
test.

package `filekv` — plus an executed failure-detection validation for the tight loop.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| N subscribed gRPC clients → one long-lived agent | Concurrent streams share one `filekv.Store`, one parser and one `*DescriptorRegistry` |
| subscriber-supplied `ConfigSubscriptionRequest.Path` → `filekv.Watch`/`Get` | An untrusted key is joined onto `protoconfRoot` to form a filesystem path and a watch registration |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-19 | Tampering | Shared `*utils.DescriptorRegistry` under concurrent `Get` from multiple streams | high | mitigate | The Phase 11/12 `d.mu` discipline is the control; Task 2's unpaced tight loop forces the read/write interleaving continuously and the lock-removal step proves the test can detect its absence. Task 1 exercises the same state through the real gRPC stream path. |
| T-14-20 | Information Disclosure | One subscriber receiving another subscriber's config value | high | mitigate | `TestFileKVConcurrentGetReturnsCorrectValuePerKey` and Task 1's per-goroutine type-URL assertions both check the value against the key that requested it, so a crossed response fails rather than passing on a shared value. |
| T-14-21 | Information Disclosure | Subscriber-supplied watch/get key escaping `protoconfRoot` | high | transferred → 14-09 | 14-07 correctly left both guards untouched, but the cited pin did not hold for a leading `..` segment in either `Get` or `Watch`.
