a containment check on `MutateConfig`'s path placed before every side effect; three tests
demonstrated capable of failing against the unfixed code; and two corrected documentation
claims.

<widened_scope>
**`server/server.go`'s `MutateConfig` write path is IN SCOPE**, widened at the user's explicit
direction after this plan's sibling audit surfaced it. It was originally recorded as
out-of-scope with disposition `transfer`; that call was reversed by the user, not by the
planner, and `T-14-25` moves to `mitigate` on the strength of Tasks 3 and 4.

`filename := filepath.Join(s.protoconfRoot, consts.MutableConfigPath, filepath.Clean(in.Path)+consts.CompiledConfigExtension)` — this is **weaker than the `filekv` defect**. `filekv` at
least carried a normalization check (insufficient, but present); this Cleans and joins with no
check at all. `consts.MutableConfigPath` is a single component, so one `../` cancels it and lands
back in `protoconfRoot`; two escape the root entirely into the `os.MkdirAll(filepath.Dir(filename))`
and `os.WriteFile(filename, ...)` below. The body is caller-supplied JSON; only the extension is
forced.

**Planner reproduction (this session, current HEAD, scratch test written and deleted).** Server
rooted at `testdata.SmallTestDir()` (itself `<T>/small` under a fresh `os.MkdirTemp` parent),
`MutateConfig` called directly with `Path: "../../escaped"` and a valid `test.v1.TestMessage` `Any`:

- returned `err=<nil>` with a non-nil response;
- logged `Written to filename=<T>/escaped.materialized_JSON`;
- left 145 bytes of caller-controlled JSON at `<T>/escaped.materialized_JSON`, outside `protoconfRoot`, containing `"stringValue": "PWNED-OUTSIDE-ROOT"`.

Two structural facts the fix must respect, both confirmed by reading `MutateConfig` in full:

1. **The pre-mutation script runs before the write.** `filename` is computed first, then the
   marshal, then `runScript(s.PreMutationScript, ...)`, then `MkdirAll`/`WriteFile`. A guard placed
   at the `MkdirAll` would still let a rejected path fire the operator's pre-mutation script. The
   guard belongs at filename computation, before every side effect.
2. **Interior separators are normal usage.** `foo/bar` legitimately means
   `mutable_config/foo/bar.materialized_JSON`, and the existing race test writes `mutate_race_N`.
   A fix that rejects separators breaks real callers.
</widened_scope>

<symlink_scope_decision>
Required explicit decision. **Out of scope, by choice.**

`filepath.Clean` and `filepath.Rel` are lexical, so a symlink *inside* `protoconfRoot` pointing outside it defeats the containment check. `filepath.EvalSymlinks` closes it at the cost of an extra syscall on every `Get`, on the agent's hot read path.

Declined because planting a symlink inside `protoconfRoot` requires write access to the config repository — a strictly larger compromise than the unauthenticated remote read this plan closes, and one that already permits writing arbitrary config content directly. Recorded as `T-14-24` (`accept`) rather than left undecided, and marked in-source with a `ponytail:` comment naming the ceiling and the upgrade path.
</symlink_scope_decision>

  `func (s *Store) resolveKeyPath(key string) (string, error)`

It is the only place in the package that turns a caller key into a filesystem path. Its logic, in order:
  1. Reject `key == ""`, and reject any key that is not already equal to its own `filepath.ToSlash(filepath.Clean(key))` form. This preserves today's normalization rejection exactly — `./x`, `a//b`, and `a/../b` keep failing as they do now.
