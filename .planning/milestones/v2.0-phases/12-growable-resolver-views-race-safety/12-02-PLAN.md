<objective>
Close the canonical-pointer hole that plan `12-01` makes reachable, and delete the dead resolver
field sitting in the struct this phase is making grow.

Purpose: `ParseFilesX`'s second lookup branch, on a resolver hit, calls `desc.WrapFile` (falling
back to `desc.CreateFileDescriptor`) and hands back a `*desc.FileDescriptor` unrelated to the
registry's canonical entry for the same file. That directly contradicts the pointer-identity
contract `ParseOne` established in Phase 11, and it is dormant today only because the resolver is
frozen and small. Growing the resolver makes the branch reachable — this phase creates the
hazard, so this phase closes it. Separately, `config.protoResolver` is assigned
`c.parser.LocalResolver` and never read; leaving a resolver reference unread in the config struct
while the resolver layer changes underneath it is how stale resolution gets reintroduced by a
future phase that "wires it up".

Output: `ParseFilesX` returns the registry's canonical descriptor for every file the registry
holds; a pointer-identity test that goes red if that regresses; and the dead field gone.
</objective>
