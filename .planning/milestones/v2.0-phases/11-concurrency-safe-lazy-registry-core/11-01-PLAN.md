<objective>
Make the compiler's proto registry lazy end to end: `GetProtoRegistry()` stops walking and
parsing all of `src/`, a proto file is parsed and linked the first time a config `load()`s it,
memoised so a second request is a map lookup, and the compiler can report how many proto files
a compile actually loaded.

Purpose: the eager parse+link at `compiler/lib/module_service.go:366` is 4,639ms of the 6.97s
compile baseline — 94% of the milestone's whole problem. Nothing else in v2.0 moves the number
this much.
Output: a concurrency-safe on-demand parse primitive in `utils`, a compiler wired onto it, and
operator-visible load-count instrumentation.
</objective>

- **D-01 (scope of laziness):** LAZY-01 applies to the **compiler's construction path only**.
  `ModuleService.GetProtoRegistry()` keeps today's eager behavior for every non-compiler
  consumer (`server/server.go:290`, `inserter/inserter.go:220`, `agent/filekv/filekv.go:80`,
  `mutate/mutate.go:73`, and `mod sync`). Making it unconditionally lazy breaks
  `inserter/inserter_test.go:21` and `:80` today, before Phase 13's symbol index exists to fix
  the fallback.
- **D-02 (Init discovery scope):** the mutation server's new eager discovery scan is scoped to
  gRPC service registration only; it does not back gRPC reflection. Owned by plan `11-02`.
- **D-03 (eager fallback is deliberate):** `utils/testdata/small/mutable_config/mutation_test.materialized_JSON`
  carries the type URL `type.googleapis.com/test.v1.TestMessage` and **no** `protoFile` hint, and
  `src/load_mutable_test.pconf` loads it as its very first statement — nothing has been parsed
  yet. A lazy-by-path registry structurally cannot answer that lookup. This plan therefore keeps
  a one-time whole-tree eager import as an explicit fallback, fired only when a type-URL lookup
  misses both the construction-time snapshot and the MessageRegistry. Phase 13 (TYPE-07) replaces
  this fallback with the on-first-need symbol index. Configs that never resolve an unknown type
  URL never pay for it.
</locked_decisions>

<assumption_delta_decision>
The detector fired on two signals. Both are real transitions in this design, and both are
`promote`.

- **Signal 1 — pluralization, "second" ("the second request is a map lookup").**
  Noun now primary: **the per-path parse request**. Decision: **promote**. The primary identity
  of a loaded proto moves from "the one whole-tree import" to "an entry in
  `DescriptorRegistry.FileRegistry` keyed by import-relative path". Every design element in this
  plan — the read lock, `singleflight` keyed on path, the memoized descriptor pointer — exists
  because the repeated per-path request, not the single bulk import, is now the unit of work.
- **Signal 2 — derived→chosen, "custom" ("a custom gRPC mutation service defined anywhere under
  `src/`").** Noun now primary: **the discovery source for the service catalog**. Decision:
  **promote**. Service discovery stops being *derived* from whatever the compiler's registry
  happened to contain and becomes an *explicitly chosen* filesystem scan of `src/`, owned by
  `Init()` (plan `11-02`, per D-02).

Neither is `add-alongside`; no accepted debt is being recorded here.
</assumption_delta_decision>

**1. `utils/utils.go` — the on-demand parse primitive.**

Add to the `DescriptorRegistry` struct: `mu sync.RWMutex` (guards `FileRegistry`, `lazyLoaded`
and `eagerFallback`), `group singleflight.Group` (imported from
`golang.org/x/sync/singleflight`, already a direct dependency at `go.mod:45` — no `go get`),
`ImportPaths []string`, `lazyLoaded map[string]struct{}`, `eagerFallback bool`. Initialize
`lazyLoaded` in `NewDescriptorRegistry` next to the existing `FileRegistry`/`localFiles` init.
Document `ImportPaths` as: when empty the registry is eager and on-demand parsing is disabled;
when non-empty those roots are the import paths on-demand parsing resolves against.

Add package-level sentinel errors next to the file's existing `errors.New` usage, following
CLAUDE.md's `Err` prefix convention: `ErrLazyParseDisabled` ("on-demand parsing requires import
paths") and `ErrUnsafeProtoPath` ("proto path escapes the import root").

Add `func (d *DescriptorRegistry) FileDescriptor(name string) (*desc.FileDescriptor, bool)` — an
`RLock`-guarded read of `FileRegistry`. Add `RLock`/`RUnlock` around the map range inside the
existing `GetFileDescriptorSet`, so a snapshot taken while another goroutine is inside `ParseOne`
cannot observe a torn map.

Add `func (d *DescriptorRegistry) ParseOne(path string) (*desc.FileDescriptor, error)`:
  - Return `ErrLazyParseDisabled` joined with the path when `len(d.ImportPaths) == 0`. This is
    what keeps every eager consumer's behavior byte-identical, and it is what keeps
    `compiler/lib/parser/parser_test.go`'s `"test not found"` case (`test1.proto`,
    `wantErr: true`) red-on-missing as it is today.
  - Reject a path that is not local to the import root with `ErrUnsafeProtoPath`, using
    `filepath.IsLocal` on the `filepath.FromSlash`ed path (threat T-11-02 below: on-demand
    parsing newly lets a `load()` string name a file outside `src/`, which the eager
    pre-populated registry could not).
  - Fast path: `RLock`, look up `d.FileRegistry[path]`, `RUnlock`, return on hit. This is
    LAZY-02's map lookup.
  - Miss: `d.group.Do(path, func() (interface{}, error) { ... })`. Inside the closure,
    re-check the map under `RLock` first (another goroutine may have finished while this one
    waited), then build a `protoparse.Parser` with `ImportPaths: d.ImportPaths`, the same
    `Accessor` closure `Import` uses (`os.Open`), and a `LookupImport` closure shaped exactly
    like `Import`'s existing one at lines 135-144 — `RLock`-guarded `FileRegistry` read first,
    then `desc.LoadFileDescriptor(s)` for compiled-in well-known types, else the same
    `fmt.Errorf("failed to find descriptor for file: %s", s)`. Do **not** set
    `InferImportPaths`; the requested path is already import-path-relative. Call
    `parser.ParseFiles(path)`.
  - **Lock discipline — the single easiest way to get this wrong:** never hold `d.mu` while
    calling `parser.ParseFiles`. `protoparse` calls `LookupImport` from inside `ParseFiles`, and
    that closure takes `RLock`; holding the write lock across the call self-deadlocks. Read,
    unlock, parse, then take the write lock only for the inserts.
  - After a successful parse take `d.mu.Lock()` and record the file **and its whole transitive
    dependency closure** — walk `fd.GetDependencies()` recursively, skipping names already in
    `FileRegistry`, writing each into `FileRegistry` and `lazyLoaded`. Recording only the
    requested file would make a later request for one of its imports re-parse it and would make
    `LoadedFileCount()` understate the real load. Call `d.MessageRegistry.AddFile("type.googleapis.com", fd)`
    for each recorded file — `msgregistry.MessageRegistry` locks internally, so that call needs
    no lock of ours.
  - Never assign to or clear `d.localFiles` anywhere in `ParseOne`. `Store` serializes exactly
    that map, and `Parse` clears it as its first statement — reusing `Parse` here is the
    LAZY-03 violation and the `mod sync` truncation risk.
  - Wrap errors with `errors.Join(errors.New("failed to parse file on demand"), err)`, matching
    this file's local idiom rather than `fmt.Errorf("%w")`.

Add `func (d *DescriptorRegistry) ParseAll() error` — the D-03 fallback. Guarded by `d.mu.Lock()`
for its whole body; returns nil immediately if `d.eagerFallback` is already true or
`len(d.ImportPaths) == 0`. Otherwise snapshot the current `FileRegistry` key set, call the
existing `d.Import(d.Parse, []*regexp.Regexp{}, d.ImportPaths...)`, then add every key that
appeared since the snapshot to `lazyLoaded`, and set `d.eagerFallback = true`. Note in a comment
that `Import`'s own `LookupImport` closure touches `FileRegistry` without locking, which is safe
here only because the caller already holds the write lock on the same goroutine.

Add `func (d *DescriptorRegistry) LoadedFileCount() int` (`RLock`-guarded `len(d.lazyLoaded)`)
and `func (d *DescriptorRegistry) FellBackToEager() bool` (`RLock`-guarded read of
`eagerFallback`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.pconf`/`.mpconf` `load()` string → on-demand proto path | A config-authored string now names a file the process opens and parses. Under the eager registry this string could only select from an already-parsed set; on-demand parsing turns it into a filesystem path. |
| `src/**.proto` → `protoparse` | Repository-local proto source parsed in-process. Pre-existing boundary, unchanged in kind by this phase — only *when* a given file crosses it changes. |
| Concurrent compile goroutines → shared `DescriptorRegistry` | `compiler/service.go:31-56` and `compiler/command.go`'s `runLocally` both run `errgroup.Go` per file against one shared `*lib.Compiler`, so one registry is written by many goroutines. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Denial of Service | `utils.DescriptorRegistry.FileRegistry` under concurrent `ParseOne` | high | mitigate | `sync.RWMutex` guards every `FileRegistry` read and write on the lazy path plus `GetFileDescriptorSet`'s range; `singleflight.Group` collapses duplicate in-flight parses. An unguarded concurrent map write is a Go fatal error that kills the whole process, not a recoverable request error. Verified by `TestParseMemoization`'s concurrency subtest and, in plan `11-03`, `TestConcurrentCompile` under `-race`. |
| T-11-02 | Tampering | `DescriptorRegistry.ParseOne` path handling | medium | mitigate | Reject any requested path that is not local to the import root (`filepath.IsLocal` on the `FromSlash`ed path) with `ErrUnsafeProtoPath`. On-demand parsing newly lets a `load()` string reach outside `src/`; the eager pre-populated registry structurally could not. |
| T-11-03 | Denial of Service | `RegistryTypeResolver`'s D-03 eager fallback | medium | mitigate | `ParseAll` is one-shot per registry (`eagerFallback` latch under the write lock), so a config resolving many unknown type URLs pays the whole-tree parse once, not once per lookup. The cost is reported on the `compile finished` line so it is visible rather than silent. |
| T-11-04 | Information Disclosure | the new `compile finished` log line | low | accept | The line emits a file count and a boolean; it names the config file already present in existing compiler logs and no proto paths or config values. |
| T-11-05 | Denial of Service | `ParseAll` holding the registry write lock across a whole-tree `Import` | low | accept | Concurrent compiles block for the duration of the one fallback import. Blocking is the correct behavior here — the alternative is duplicate whole-tree parses — and the latch bounds it to once per process. |

No package-manager installs occur in this phase; `golang.org/x/sync` is already a direct
dependency at `go.mod:45`, so the package-legitimacy gate does not apply and no `T-11-SC` row is
required.
