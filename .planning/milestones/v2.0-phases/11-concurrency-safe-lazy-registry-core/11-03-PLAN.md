<objective>
Prove the concurrency claim in this phase's name, and guard the one thing laziness must not
touch. Two pieces: make the compiler's `MessageRegistry` shared by pointer so concurrent
compiles read and write through one mutex, and lock in that `mod sync`'s `.fds` output is
unchanged by everything plan `11-01` did.

Purpose: `compiler/service.go`'s `CompileFiles` handler and `compiler/command.go`'s `runLocally`
both already run `errgroup.Go` per file against one shared `*lib.Compiler`. Nothing in the test
suite exercises that shape, so the race the lazy path introduces would be found by CI or by a
user, not by this phase.
Output: a real concurrent-compile race test, the pointer fix that makes it pass, and a `.fds`
byte-identity regression guard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Concurrent compile goroutines → shared `msgregistry.MessageRegistry` | `compiler/service.go`'s gRPC `CompileFiles` handler and `compiler/command.go`'s `runLocally` both fan out over one shared `*lib.Compiler`; on-demand parsing makes `AddFile` a mid-compile writer. |
| `.protoconf_cache/*.fds` on disk → any later process that `Load`s it | A `.fds` written by `mod sync` is consumed by a different process, potentially on a different machine, and its md5 checksum validates the bytes present rather than their completeness. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-10 | Denial of Service | `config.messageRegistry` value copy at `compiler/lib/compiler.go:355` | high | mitigate | Share the registry by pointer so every reader and the `AddFile` writer take the same `sync.RWMutex`. A value copy carries an independent zero-value mutex over shared maps, which is an unsynchronized concurrent map access — a Go fatal error that terminates the process. Verified by `TestConcurrentCompile` under `-race -count=2` and by `go vet` reporting no copylocks finding. |
| T-11-11 | Tampering | a truncated `.fds` written by `mod sync` | high | mitigate | `TestModSyncFdsByteIdentical` pins the eager path's serialized bytes against an independently constructed eager registry. `Store` computes its md5 over whatever it wrote, so a truncated cache validates against its own checksum and is silently accepted by `Load` in a later process — checksum validation cannot detect this class of corruption and a byte-identity test is the only guard. |
| T-11-12 | Repudiation | a race that only appears on a warm second run | medium | mitigate | The concurrent test runs with `-count=2` so an interleaving that requires a partially populated cache is exercised, not just the cold-cache path. |
| T-11-13 | Denial of Service | test-authored `.pconf` fixtures written into `t.TempDir()` | low | accept | Fixtures are generated by the test into a per-test temporary directory the Go runtime removes; no repository file is written. |

No package-manager installs occur in this plan, so the package-legitimacy gate does not apply and
no `T-11-SC` row is required.
</threat_model>
